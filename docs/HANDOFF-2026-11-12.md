## 3. 내일 이어서 할 것

### A. 먼저 확인 (10분)

1. **사용자 PC에서 옛 화면이 보인 문제**: 사용자가 보낸 화면이 새 HTML에 옛 `home.css`가 입혀진 모습이었습니다. 이 세션의 정적 서버(Python)는 캐시 헤더가 없어 브라우저가 옛 CSS를 들고 있었을 가능성이 가장 큽니다. 내일 첫 질문: 어떤 주소로 보셨는지(`localhost:8532`, `npm run dev`의 `localhost:4000`, Live Server, `file://`). Ctrl+F5 후에도 옛 모습이면 그 서버가 다른 폴더나 옛 빌드를 보는 것입니다. 필요하면 캐시를 쓰지 않는 확인용 서버를 띄웁니다.
2. **직접 못 본 것**: ① 제품 행에 실제 마우스를 올렸을 때 Sage 선이 그어지는 모습, ② "모션 줄이기"를 켠 상태(Windows 설정 → 접근성 → 시각 효과 → 애니메이션 효과 끄기)에서 자동 진행이 없고 제자리 페이드만 되는지, ③ 스테퍼가 마우스·키보드 포커스에서 멈추는지.

### B. 결정이 필요한 것

1. 브라우저 탭 제목(`<title>`)과 검색 설명문에 새 슬로건을 넣을지. 지금은 "FINDER GREEN 파인더그린 - 골프 브랜드를 위한 소싱·제작 파트너"입니다.
2. 홈의 디자인·모션을 **다른 페이지**(견적 허브, 견적 폼 3종, 내 견적, 로그인, 기타 문의)로 넓힐지. 지금은 홈만 재디자인했고 나머지는 색·톤·굵기·간격만 새 기준입니다.
3. 말투를 통일할지. 홈 한 줄 설명은 동사 없이 끝나는 명사형, 견적 페이지의 같은 자리는 "~합니다"입니다. 전부 "~합니다"로 맞추는 방법도 있습니다.
4. 참고 영상의 **대시보드**(좌측 메뉴, 일정, 확인 요청, AI 견적 목록, 알림 설정, 카카오 채널 채팅) 방향으로 내 견적 화면을 키울지. 키운다면 요구사항 정리가 먼저입니다. 카카오 연동은 아직 검증되지 않았습니다.

### C. 만들 수 있는 것

- 모션을 다른 페이지로 확장(B-2를 정한 뒤): 견적 허브의 제품 선택 카드에 파인더 링, 견적 결과 화면에 단계 모션 등.
- Hallmark 화면 캡처 점검: `puppeteer-core`를 설치하면 `sloplint --render`와 비교 화면(`compare.html`)을 쓸 수 있습니다. 설치는 새 의존성 내려받기라 사용자 승인 후에 합니다.
- 서버가 만드는 문구: 이메일 본문과 서버 오류 메시지(`src/`)는 아직 "~해요" 말투입니다. 고객이 받는 메일이라 같은 톤으로 맞출지 정해야 합니다(이메일 제목 `[Bridge Path] …` 포함).
- 관리자 화면(`admin-ui/`)과 `privacy-consent.html`: 문구를 바꾸지 않았습니다. 동의 문구는 승인 전이라 바꾸지 않습니다.
- `estimate.html` 푸터의 가운뎃점 줄(홈 푸터는 줄마다 나눔).
