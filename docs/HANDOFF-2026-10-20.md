# 인수인계: Bridge Path 견적 서비스 (2026-10-20 기준)

새 Claude 세션(다른 PC, VS Code 등)이 이 파일과 `AGENTS.md`만 읽고 이어서 작업할 수 있게 정리한 문서입니다.
오늘의 대화는 다른 기기로 넘어가지 않으니, 맥락은 이 문서와 저장소(커밋 기록, README, docs)에 있는 것이 전부입니다.

## 1. 저장소와 규칙
- 저장소: `Evan-BPcompany/bridgepath-renewal`, 작업 브랜치 `develop/bmad-setup`.
- 먼저 `AGENTS.md`를 읽을 것. 핵심: 커밋과 push는 **사용자가 요청할 때만**, `.env`는 읽거나 출력하지 않기, 실제 DB에 마이그레이션 실행 금지, 외부 서비스(S3, SendGrid, Claude API)는 승인 없이 호출 금지.
- 새 환경에서: `git pull`, `npm install`, `.env`를 새로 만들고(키는 git에 없음) `ANTHROPIC_API_KEY`를 넣을 것. `.env`는 `.gitignore` 대상.
- 검증 명령: `npm run build`, `npm test -- --runInBand`(마지막 전체 실행 **1831개 통과**), `npm run secret-scan`, `npm run audit:prod`(취약점 0).
- 통합 테스트(실제 PostgreSQL): 사용자가 **자기 터미널**에서 `TEST_DATABASE_URL`(이름에 `test`가 들어간 로컬 DB)을 설정하고 `REQUIRE_INTEGRATION=true npm run test:integration`을 실행해야 함. 에이전트 세션에는 접속 정보가 없으니 직접 돌리지 말고 사용자가 돌린 결과를 기록할 것. 마지막 결과: **10 스위트, 268 테스트 통과**(PostgreSQL 16, 이 개발 PC).
- 미추적으로 남겨 둔 것: `glasses/`(테스트 사진 6.8MB), `.claude/.claude/` — 스테이징하지 말 것.

## 2. 지금 있는 것 (모두 커밋·push됨)
**선글라스 AI 견적** (`sunglasses-estimate.html`)
1. 사진 업로드 → `POST /api/estimate-preview/analyze-image`가 Claude로 재질·렌즈·형태·비용 요인 등을 분석(스키마 검증된 JSON). 기본 모델 `claude-opus-5-5`(`IMAGE_ANALYSIS_MODEL`로 변경). 키가 없으면 503이고 폼은 그대로 동작.
2. 재질·렌즈 자동 선택(사용자가 고른 값은 덮어쓰지 않음), 1MB 넘는 사진은 브라우저에서 1600px JPEG로 축소.
3. 수량 입력 후 **AI 견적 시작** → 결과 화면(`estimate-result.js`): 사진, 종합 분석, 인식 결과, 예상 비용, 상세 분석, 비용 요인, 권고사항.
4. 가격은 규칙 계산(`POST /api/estimate-preview`): 기준가(`base_prices`) × 렌즈 보정 × 수량 구간 보정, ±15% 범위. 분석 문구는 가격·국가·공장을 말하지 못하게 프롬프트로 막음. 8% 수수료는 AI 안내에 노출하지 않음(PRD 결정).
5. **정식 견적 요청하기** → 고객 정보 → 제출.

**접수(모든 페이지: 선글라스, 신발, 골프, 기타 문의)**
- 공통 제출 코드 `estimate-submit.js`, 첨부 컴포넌트 `estimate-attachments.js`(JPG/PNG/WEBP/PDF, 파일당 10MB, 5개, 합계 30MB).
- 선글라스는 분석에 쓴 사진이 자동 첨부(표시됨, 뺄 수 있음). 요청에는 화면에 보였던 분석과 가격 범위가 `specification_json.ai_preview`로 따라감(참고 기록일 뿐 신뢰하지 않음, 형식이 틀리면 버리고 접수는 계속).
- **전부 저장되거나 전부 저장되지 않음(PRD FR-4.7)**: 파일을 저장소에 먼저 올리고, 견적·토큰·이메일 대기열·파일 행을 한 트랜잭션으로 기록. 실패하면 파일 제거, 접수번호 없음. 5xx 응답은 "접수되지 않음"으로 안내.
- 저장소: `FILE_STORAGE=s3`(기본) 또는 `local`(개발용 폴더 `uploads-dev`, 운영에서는 거부).
- 접수 후 영수증: 접수번호(복사 버튼), 접수 시각, 제출 내용 요약(제품, 가격 범위, 연락처, 첨부 이름).

**기준가** (마이그레이션 `014_sunglasses_base_prices.ts`, **어떤 DB에도 적용하지 않음**)
- 플라스틱 2,600 / 메탈 5,190 / 우드 6,750 / 혼합 8,620 / 아세테이트 9,810원. Made-in-China.com 공장 가격 중간값 × 1,330.79원/달러(2026-10-20). Alibaba는 봇 차단으로 쓰지 못했고 우회하지 않음.
- 근거 데이터 `docs/pricing/`, 계산 `node scripts/sunglasses-base-prices.js`. 마이그레이션과 스크립트가 다르면 테스트가 실패함.
- 공장 출고가 기준(배송·관세·금형·로고·포장·수수료 제외)이라 고객에게 그대로 보여주면 실제보다 낮음. 렌즈 보정과 수량 구간 보정은 **임시값**.

**개인정보 동의 문구**: `docs/privacy-consent/DRAFT-2026-10-20.md`(초안, 승인 전 사용 금지, `[결정 필요]` 항목 있음). 승인된 버전이 없으면 운영 서버는 접수를 받지 않음(503).

## 3. 아직 안 된 것 / 검증되지 않은 것
- **관리자 화면(UI)**: 백엔드 관리자 API는 있으나 화면이 없음. 지금은 접수가 들어와도 담당자가 볼 방법이 없음. → **다음 작업 1순위.**
- 첨부 파일의 관리자 열람(다운로드)은 의도적으로 막혀 있음(바이러스 검사 없음, PRD FR-5.4). 관리자 화면 1차에서는 파일 이름과 상태만 보여줄 것을 제안.
- 실제 **AWS S3**와 **SendGrid 이메일**은 한 번도 호출·검증하지 않음.
- 신발·골프에는 AI 견적이 없음(선글라스만). 홈페이지 신뢰 콘텐츠(진행 단계, FAQ, 포트폴리오)는 없음.
- 개인정보: 보관 기간, 사진의 국외(미국) AI 서비스 전송 고지, 처리 위탁 업체, 책임자 연락처를 정해야 함. 자동 삭제 기능은 없음.
- 사진 분석은 실제 Claude API로 **사진 1장**만 시험함. 재질이 다른 사진, 어두운 사진, 선글라스가 아닌 사진을 더 시험해야 하고, 아세테이트와 플라스틱 구분은 사진만으로 틀릴 수 있음(화면에서 수정 가능).
- 운영 배포(맨 마지막으로 정함): `config.js`의 `API_BASE`(지금 localhost:4000), 서버 CORS 허용 출처, `TRUST_PROXY=1`, 서버의 `ANTHROPIC_API_KEY`, `FILE_STORAGE=s3`와 AWS 설정, 승인된 동의 문구, 마이그레이션 실행(014 포함).

## 4. 비용과 키
- Claude 콘솔에 API 크레딧 $5를 선결제함. 사진 분석은 호출마다 차감되는 유료 호출이니 실제 API 시험은 필요한 만큼만 하고 먼저 사용자에게 알릴 것. 호출당 비용은 아직 측정하지 않음(추정 몇 센트). 응답 토큰 사용량을 서버 로그에 남기면 정확히 알 수 있음.
- IP당 시간당 10회로 분석 호출을 제한(`CUSTOMER_IMAGE_ANALYSIS_RATE_LIMIT_*`). 서버가 여러 대면 제한도 서버마다 따로 계산됨.
- 키는 절대 채팅이나 git에 넣지 말 것.

## 5. 알아둘 함정
- `estimate-common.js`는 사진을 한 번 고르면 업로드 상자의 `innerHTML`을 바꿔 `<input id="sunglassImage">`가 문서에서 빠짐(페이지는 갖고 있던 요소로 계속 동작). 테스트는 요소 참조를 따로 잡음.
- Multer는 파일명을 Latin-1로 읽어 한글이 깨짐 → `decodeFilename`으로 복원(실제 DB 테스트로 확인).
- DOM 테스트에서 페이지마다 `BridgePathResult`, `BridgePathPreview`, `BridgePathAttachments` 전역이 남아 다음 테스트에 새므로 `afterEach`에서 지울 것.
- 마이그레이션 통합 테스트(`migrations.int.test.ts`)는 013까지만 다루는 스키마 테스트이고, 014(가격만 씀)는 같은 파일 끝에 전용 테스트가 있음.
- Windows라 LF→CRLF 경고가 많이 나옴(무시해도 됨). 스크립트를 셸 heredoc으로 넘길 때 `\u0000` 같은 이스케이프가 실제 문자로 바뀌는 문제가 있었음 → 그런 코드는 파일로 쓸 것.
- 앱을 눈으로 확인하려면 임시 데모 서버가 필요함(저장소에 없음): 빌드된 `dist/app.js`를 쓰고 DB와 사진 분석은 가짜로 바꿔 `localhost:4000`에서 정적 파일과 `/api`를 함께 제공.
