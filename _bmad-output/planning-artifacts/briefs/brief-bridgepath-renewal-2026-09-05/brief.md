# Product Brief: Bridge Path OEM/ODM 견적 문의 사이트

## Executive Summary

Bridge Path는 선글라스·신발·골프용품 등을 실제로 제조해온 경험을 바탕으로, 브랜드/사업자의 맞춤 제작(OEM/ODM)을 견적부터 생산까지 지원하는 회사다. 현재 웹사이트는 회사소개와 4개 카테고리(선글라스, 신발, 골프용품, 기타)의 견적 문의 폼을 갖춘 정적 프론트엔드로, 실제 견적 산출·데이터 저장·로그인 기능은 아직 없다.

이 브리프는 두 가지를 한다. 첫째, 지금 저장소가 실제로 무엇으로 구성되어 있는지를 있는 그대로 정리한다. 둘째, 향후 방향 — 골프화·선글라스 중심의 견적 문의 고도화, 로그인/견적현황/제작현황/마이페이지로의 확장 — 을 정리해 다음 단계인 PRD가 "4개 카테고리를 유지할지 축소할지", "확장 기능을 어떤 순서로 붙일지"를 결정할 근거로 삼는다.

## Current State (현재 상태 — 사실 기록)

**기술 스택**: 빌드 도구·프레임워크·백엔드 없음. 순수 HTML/CSS/JavaScript 정적 파일로만 구성.

**페이지 구조**:
- `index.html` — 회사소개(`#about`), 서비스(`#services`), 문의(`#contact`) 섹션이 있는 랜딩 페이지. "중국 OEM 제조 5년 이상의 경험" 등 선글라스·신발·골프용품 실제 제조 경험을 강조.
- `estimate.html` — 4개 카테고리(선글라스/신발/골프용품/기타)로 진입하는 허브 페이지.
- `sunglasses-estimate.html`, `shoes-estimate.html`, `golf-estimate.html` — 카테고리 선택 → 상세 정보 입력의 2단계 스텝 폼. 세 페이지 모두 `estimate-common.js`/`estimate-common.css`를 공유하는 동일 패턴.
- `other-inquiry.html` — 단일 스텝 구조로 별도 구현(공유 스크립트 사용 안 함).

**폼 제출 동작**: 모든 견적 폼은 입력값을 `console.log`로만 출력하고, 성공 메시지를 보여준 뒤 홈으로 리다이렉트한다. 서버 전송, DB 저장, 실제 견적 계산 로직은 없다.

**UI 카피와 실제 구현의 간극**: 홈페이지와 견적 허브의 버튼/문구는 "AI 견적받기", "AI 기반 견적 시스템이 최적의 제조 방안을 제안합니다" 등 AI 기능을 표방하지만, 실제 코드에는 AI 관련 로직이 전혀 없다 — 현재는 마케팅 카피만 있고 그 뒤에 실제 기능은 없는 상태.

**알려진 버그**: `index.html`이 불러오는 `script.js`는 `index.html`에 존재하지 않는 `#estimateForm` 엘리먼트를 참조해서, 홈페이지를 열 때마다 콘솔 에러가 발생한다.

**없는 것**: 로그인/회원가입, 마이페이지, 견적현황·제작현황 조회, 결제, 실제 서버·데이터베이스.

*(저장소의 파일별 상세 구조는 `addendum.md`의 "현재 저장소 상세 인벤토리" 참고)*

## The Problem

Bridge Path는 선글라스·신발·골프용품 제조 경험을 실제로 갖춘 회사지만, 지금 웹사이트는 그 경험을 "견적을 받아본다"는 실질적 액션으로 연결하지 못한다. 방문자가 폼을 채워도 실제로는 아무 곳에도 전달되지 않고(`console.log`만 됨), 이후 진행 상황을 확인할 방법도 없다. 또한 "AI 견적"을 내세우는 카피가 실제 기능과 어긋나 있어, 방문자가 기대하는 것과 실제로 받는 경험 사이에 격차가 있다.

동시에 사업 방향은 이미 4개 카테고리 전체를 넓게 다루기보다 골프화·선글라스로 좁혀 깊게 파고드는 쪽으로 기울고 있는데, 지금 사이트 구조(4개 카테고리 동일 비중)는 이 방향을 반영하지 못하고 있다.

## Future Direction (향후 방향)

- **핵심 카테고리 강화**: 골프화·선글라스 제작 견적 문의를 중심으로 발전시킨다. (일반 신발·기타 카테고리의 유지/축소 여부는 이 브리프에서 결정하지 않고 PRD 단계로 넘긴다.)
- **회사소개는 유지 및 개선**: 기존 `index.html`의 회사소개 콘텐츠(제조 경험, 강점)는 그대로 유지하되 개선한다.
- **로그인 기반 기능으로 확장**: 로그인, 견적현황, 제작현황, 마이페이지를 순차적으로 추가할 계획. 이는 정적 프론트엔드에서 실제 백엔드/DB/인증이 필요한 서비스로의 전환을 의미하며, PRD·아키텍처 단계에서 범위와 순서를 정한다.
- **수리/AS 서비스 아님**: 신규 제작(OEM/ODM) 견적 문의가 핵심이며, 카피나 기능이 수리 접수처럼 보이지 않도록 한다.

**[ASSUMPTION]** 사용자가 현재 선글라스를 실제로 제작·판매하고 있다고 밝혔고, 사이트의 "선글라스 OEM 5년 경험" 소개 문구와 맞닿아 있다 — 즉 이 웹사이트가 대표하는 사업과 사용자가 이미 운영 중인 선글라스 제조·판매업이 같은 사업이라고 가정했다. 다르다면(별도 사업이거나 사이트가 별도 신규 브랜드라면) 관계를 확인해달라.

## Reference Cases (참고 사례)

다음 단계 방향(특히 로그인/견적현황/제작현황 확장)에 참고할 실제 사례 3곳을 확인함.

- **[sinple.co.kr](https://www.sinple.co.kr/)** — AI 기반 신발 제조 플랫폼. 실시간 AI 견적, 로그인/마이페이지, 생산 단계별(자재수급→생산중→검수중→배송중) 현황 대시보드를 갖춤. Bridge Path가 향후 만들려는 "로그인 + 견적현황 + 제작현황" 구조와 가장 가까운 실제 사례.
- **[shoedogkorea.com](https://shoedogkorea.com/)** — 24년 경력 신발 제조사. 6단계 제조 프로세스를 안내형 랜딩페이지로 설명하지만 로그인/마이페이지는 없이 문의 폼과 전화/이메일로만 응대 — 지금 Bridge Path 사이트와 비슷한 수준.
- **선글라스 특화 사이트**(사용자 제공, 봇 차단으로 자동 확인 불가) — 사용자가 마음에 들어한 부분은 안경·선글라스를 종류별 카테고리와 소재별 설명으로 정리한 구성. 선글라스 카테고리의 상품 정보 구조를 다듬을 때 참고할 것.
- **골프용품은 참고할 만한 사이트를 찾기 어려웠다**(사용자 관찰) — 벤치마크가 마땅치 않은, 상대적으로 비어 있는 영역일 수 있음.

*(각 사이트의 세부 항목은 `addendum.md` 참고)*

## Who This Serves

맞춤 제작(OEM/ODM)을 필요로 하는 브랜드·사업자 — 특히 골프화, 선글라스를 자체 브랜드로 만들어 팔고 싶은 국내 소규모~중견 사업자. **[ASSUMPTION]** 구체적인 타겟(개인 창업자 vs 기존 브랜드사, 국내 한정 vs 해외 포함 등)은 사용자 확인이 필요한 부분으로 남겨둔다 — PRD 단계에서 페르소나를 더 구체화할 것.

## Scope

**이번 브리프에서 확정한 것**:
- 수리/AS가 아닌 신규 제작 견적 문의가 핵심이라는 포지셔닝
- 골프화·선글라스를 핵심 카테고리로 밀되, 기존 회사소개 콘텐츠는 유지·개선
- 로그인/견적현황/제작현황/마이페이지가 다음 확장 방향이라는 것

**PRD 단계로 넘기는 열린 질문**:
- 기존 4개 카테고리(선글라스/신발/골프/기타) 중 신발·기타를 유지할지, 축소하거나 없앨지
- 로그인/견적현황/제작현황/마이페이지의 우선순위와 최소 범위(MVP)
- "AI 견적" 카피에 맞춰 실제로 자동 견적 로직을 넣을지, 아니면 카피를 사람이 응대하는 방식에 맞게 바꿀지
- 목표 고객이 누구인지(개인/소규모 사업자 vs 기존 브랜드사)에 대한 구체화

## Vision

지금은 방문자가 카테고리를 고르고 정보를 입력해도 그 뒤로 아무 일도 일어나지 않는 정적인 문의 페이지지만, 방향이 그리는 다음 모습은 sinple.co.kr류의 구조에 가깝다 — 방문자가 로그인해서 견적을 요청하고, 그 견적이 실제로 처리되는 과정(제작현황)을 마이페이지에서 확인할 수 있는 서비스. 다만 Bridge Path는 모든 카테고리를 넓게 가져가기보다, 이미 실제 제조·판매 경험이 있는 선글라스와 새로 힘을 싣는 골프화에 집중해서 깊이를 만드는 쪽을 택하고 있다.
